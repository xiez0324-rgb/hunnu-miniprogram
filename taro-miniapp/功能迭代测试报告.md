## 一、功能 1：多学段分档薪资

### 1.1 设计说明

- 数据模型：`resumes` 集合新增字段 `rateByStage`（对象，键=学段，值=`'min-max'`），保留原 `rate` 作为“统一时薪”兼容字段；二者可并存。
- 入口：老师端「我的 → 简历管理」。
- 保存/读取：`saveResume`（云函数，按 `_openid` upsert，支持分档字段）；`getMyResume`（云函数，新增，编辑页进入回填）。
- 展示：家长端「老师简历页」期望时薪区——有分档则逐学段列出（如 `初中 110-130 元/时`），无分档回退统一时薪；报名快照 `rate` 自动生成分档摘要（如 `初中110-130元/时·高中130-150元/时`）。
- 前端校验规则（保存前拦截并 toast）：
  1. 科目/年级/时段/区域/自我介绍任一为空 → 拦截；
  2. 统一时薪：可空；填写则须为 20~600 的数字；
  3. 分档：整行可留空；填了一端必须两端完整；须为数字且 20~600；最低 ≤ 最高；
  4. 统一时薪与分档均未配置 → 提示至少配置其一。

### 1.2 涉及文件

| 文件 | 说明 |
|---|---|
| `cloudfunctions/saveResume/index.js` | 支持 `rateByStage` 字段存取 |
| `cloudfunctions/getMyResume/*`（新增） | 读取当前老师简历供回填 |
| `src/pages/resume/index.tsx`、`*.module.scss` | 受控表单重构 + 分档区间 UI |
| `src/pages/teacher-detail/index.tsx`、`*.module.scss` | 分档薪资展示 |
| `cloudfunctions/applyDemand/index.js` | 报名快照 rate 分档摘要 |
| `src/types/index.ts`、`src/data/*`（mock） | 类型与 H5 mock 同步 |

## 二、功能 2：个人信息管理页

### 2.1 设计说明

- 页面：改造原「我的联系方式」→ **「个人信息」**（`pages/contact/index.tsx`），家长/老师共用同一入口与页面；「我的」菜单双端改名。
- 字段：身份标识（只读，来自登录角色）、姓名/称呼（必填 ≤20 字）、联系电话（老师必填，11 位且 1 开头；家长选填）、微信号（选填 ≤50 字）、所在区域（老师必填；其余 ≤50 字）。
- 保存链路：`updateProfile` 云函数（新增）→ `users` 集合，白名单仅更新 `nickname/phone/wechat/area`，**role 不可经此接口修改**；服务端同规则二次校验。
- 权限：`getProfile`/`updateProfile` 均按 `_openid` 定位，仅可读改本人档案。
- 反馈：成功 toast「个人信息已保存」；各类非法输入均有明确文案提示。

## 三、功能 3：联系代理人跳转

### 3.1 设计说明

- 入口：家长端需求确认页「联系代理人」卡片（当前系统唯一可交互联系入口）。
- 交互链路：点「联系代理人」→ 二次确认弹窗（文案按环境区分）→ 确认后：
  - **微信小程序内**：出现 `open-type="contact"` 客服按钮，点击拉起微信内置客服会话；
  - **H5 / 外部浏览器**：自动复制客服微信号 `agentWechat` 并 toast 引导前往微信添加（复制失败给出手动记录引导）。
- 客服号配置：`src/data/shared.ts` → `agentWechat`（当前为演示占位，正式运营替换为真实客服号）。

5. **历史数据**：早期 `rate` 为“120 元/时”含单位文本，编辑页回填会自动抽取数字，兼容保存为纯数字。

- 入口：角色选择页底部低调「管理后台入口（仅限管理员）」→ 账密登录 → 工作台；管理页不占 tabBar。
- 会话：`admin_token / admin_user` 本地存储，admin 云调用统一携带 token，云端 `requireAdmin` 鉴权不变。
- 鉴权守卫：每个 admin 页 onShow 检查登录态，未登录重定向登录页；退出/改密成功后清会话回登录页。
- 适配要点：rpx（750 基准）+ 安全区（底部 `env(safe-area-inset-bottom)`）；PC 侧边栏/表格改为「工作台宫格 → 二级卡片页」；列表触底分批渲染 + 下拉刷新；所有写操作（订单流转/审核通过/驳回/登记费用/改密/退出）均二次确认；按钮/标签热区 ≥ 88rpx。
- 服务层：`services/admin.ts`（token 存取 / callAdmin 短缓存 / fileID→临时链接），`data/adminMocks.ts` 为 14 个 admin 云函数提供 H5 mock。

### 7.2 图片浏览能力（本轮核心）

| 能力 | 实现方式 |
|---|---|
| 双指缩放 / 左右滑切 / 长按保存 | 微信原生 `Taro.previewImage`（主通道，零内存压力） |
| 手势降级（含缩放/平移/滑切） | `components/ImageGallery`：原生失败 / 含历史文本记录 / 部分图缺链接时自动降级自研全屏画廊（捏合缩放、拖动、左右滑切、还原） |
| 单张保存到相册 | `utils/imageUtil.saveGalleryImage`：下载→`saveImageToPhotosAlbum`；授权被拒→showModal→`openSetting`→授权后自动重试一次（含微信隐私接口授权） |
| 网络失败降级 / 重试 | `components/LoadableImage`（缩略图占位+点击重试）、画廊错误面板（重新加载） |
| 大图预加载 | 切换时对相邻图经 `wx.cloud.downloadFile` 静默预热（云链路，无需域名） |
| 加载进度 / 弱网容错 | 微信端当前大图经 `wx.cloud.downloadFile(fileID)` 下载并带 onProgressUpdate 百分比；失败文案区分“网络不佳，图片下载超时”；云链路无需配置 downloadFile 域名 |
| 零域名设计（上线关键） | 微信端展示/预览/保存全程用 cloud:// fileID：`<Image>` 直显、`wx.previewImage` 直传 fileID（官方支持云文件 ID）、`wx.cloud.downloadFile` 下载后存相册 —— 全部走微信云开发私有链路，不依赖任何 request/downloadFile 域名白名单，无需备案域名 |
| 历史文本材料 | 无云图时画廊展示文本面板（核验仍可参考文字说明） |

涉及文件：`components/ImageGallery/*`、`components/LoadableImage/*`、`utils/imageUtil.ts`、`services/admin.ts`；接入场景：admin 学籍审核材料多图、老师端实名认证已上传照片（点击查看大图/保存）。

### 8.3 多账号数据隔离：发现的越权漏洞与修复

### 8.4 健壮性与性能检测报告

> 说明：本报告为**代码级静态评估**。真实并发压测必须在云函数部署后用真机/压测工具执行，本节不含任何未经实测的性能数字。

#### A. 发现项与风险分级

| 级别 | 发现 | 位置 | 影响 |

| 中 | **报名 5 条上限为 check-then-act 非原子**：`count` 与 `add` 之间若并发同一用户两次调用，可能写入 2 条突破上限 | `applyDemand` | 极低频（前端有按钮 loading 防抖），但理论上可被脚本绕过 |
| 中 | **重复报名判定同为 check-then-act**：同需求同老师的"活跃唯一"约束靠查询判断，无唯一索引兜底 | `applyDemand` | 并发下可能产生两条活跃报名 |
| 中 | **无显式上限的读取**：老师端「我的报名」`applications.where(_openid).orderBy().get()` 未显式 limit（服务端默认 100） | `getMyData` | 数据量增长后历史记录被静默截断（功能问题 > 性能问题） |
| 中 | **全量取出内存统计**：`adminDashboard` 对 `fee_records` 全表 `get()` 后在内存累加 | `adminDashboard` | 台账量级增大后单次调用耗时/内存上升 |

| 低 | **索引未声明**：需求列表（`status+auditStatus+createTime`）、报名（`demandId+teacherId`、`_openid+status`）、匹配（`demandId+status`）等高频条件未确认已建索引 | 全库 | 数据量增长后扫描行数上升，延迟非线性增长 |

#### B. 优化方案（按性价比排序）

1. **建索引（最高性价比，无需改代码）—— ✅ 已于 2026-09-12 通过 CloudBase MCP 在云端创建完毕**
   创建前现状：所有集合仅有默认 `_id_` 与 `_openid_1`（微信云开发自动创建），**无任何复合索引**。已新增 14 个索引：

   | 集合 | 新增索引 | 覆盖场景 |
   |---|---|---|
   | `demands` | `id_1`、`(status, auditStatus, createTime DESC)` | 详情/报名按 id 查、广场列表过滤+排序 |
   | `applications` | `(demandId, teacherId, status)`、`(demandId, status)`、`(_openid, status)`、`teacherId_1` | 报名幂等校验、家长端报名名单、老师「我的报名」、管理端 join |
   | `matches` | `(demandId, status)`、`(demandId, teacherId, status)`、`(teacherId, status)`、`status_1` | 确认/取消匹配、管理端订单列表与筛选 |
   | `teacher_users` / `parent_users` | `(userId, _openid)` | 登录建档、档案读写双条件定位 |
   | `audit_logs` | `createTime DESC` | 操作日志倒序查询 |
   | `verifications` | `status_1` | 管理端学籍审核按状态筛选 |

   说明：`demands.id` 采用**普通索引而非唯一索引**，原因是历史/兼容数据可能存在「无 id 字段」的文档，非稀疏唯一索引会把多个缺失值视为重复 null 而拒绝写入，存在写失败风险；如需强制唯一，可在确认全量数据均含 id 后再升级。
   已存在 `_openid_1` 的集合不再重复建同字段索引；`resumes`（1 条）、`fee_records`（0 条）数据量过小，未额外建索引。
2. **报名上限与重复报名改原子化**（注意：微信云开发事务**不支持 `where` 查询**，事务内仅支持单记录 `doc` 操作 + `add`，因此不能"在事务里 count + add"）：
   - **重复报名**：给 `applications` 建**唯一索引 `(_openid, demandId)`**。本项目同一老师同一需求只保留一条文档（取消后复用同一条恢复），天然满足唯一性；并发重复写入会被数据库直接拒绝。
   - **5 条上限**：把"报名中数量"落到 `teacher_users` 的计数字段，用 `_.inc(1)`（更新指令为原子操作）自增后再判断，超限则 `_.inc(-1)` 补偿；或采用"先 add、再复核 count、超限则删除自己刚写入的那条"的补偿式写法。
3. **读取显式分页**：`getMyData`（老师报名）改为 `limit(20) + 分页`；`getDemands` 已是 `skip/limit` 分页，保持。
4. **费用汇总改聚合**：`adminDashboard` 用 `count()` + 聚合（或维护汇总字段）替代全表 `get()`。
5. **减少串行往返**：`applyDemand` 中 `verifications` 与 `resumes` 可并行（`Promise.all`），预计减少 1~2 次 RTT。
6. **包体优化**：mock 模块改为 `process.env.TARO_ENV !== 'weapp'` 条件引入或构建期剔除。
7. **可观测性**：在云函数中对 DB 调用打耗时日志；用云开发控制台「云函数监控」观察 P95 耗时、错误率、并发实例数，作为后续压测基线。
8. **高频切换节流**：`useDidShow` 刷新（Plaza/MyApplications/MyDemands）加 3~5 秒时间窗，避免快速切 tab 造成重复请求。

#### C. 并发承载的实测方案（部署后执行）

1. 在云开发控制台查看当前「云函数并发配额」与「数据库连接数配额」上限；
2. 用 `wx.cloud.callFunction` 或云开发「云函数压力测试」对 `getDemands` / `getDemandDetail` / `applyDemand` 三个高频接口施压（建议 20 / 50 / 100 并发梯度）；
