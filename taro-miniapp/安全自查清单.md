# 安全自查清单

> 适用工程：`taro-miniapp`（二号开发版本）
> 目的：小程序上线后的**实际攻击面**排查。代码层面已做的加固见文末「已完成的代码加固」。
> 更新：2026-09-21

---

## 为什么这份清单是必要的

微信云开发的**云函数**与**数据库/云存储权限**是**两套独立机制**：

- 你在云函数里写的归属校验（`_openid` 比对、`requireAdmin`）只在"数据经由云函数"时生效；
- 一旦某个集合被设成"所有用户可读/可写"，攻击者可以**完全绕过云函数**，用 CloudBase SDK 直接读写数据库。

而**云环境 ID 不是秘密**——它由 `Taro.cloud.init` 打包进小程序客户端，任何用户都能从包里提取（本项目 `dist/app.js` 中即为明文）。

**结论：云函数写得再严，数据库权限设错就全盘失效。这是本项目第一优先级的安全项，且只能在控制台核查。**

---

## P0 — 数据库集合权限（必做，最高优先级）

路径：**云开发控制台 → 数据库 → 选中集合 → 权限设置**

逐个集合确认，**全部应为「仅管理端可读写」**（即只有云函数能访问，客户端不可读写）：

| 集合 | 若被设为「所有用户可读」的后果 |
|---|---|
| `parent_users` | **全站家长手机号泄露** |
| `teacher_users` | **全站老师手机号泄露** |
| `resumes` | 老师简历与联系方式泄露 |
| `verifications` | **学籍/学生证等身份材料泄露** |
| `admins` | 管理员账号与 `passwordHash` 泄露，可离线爆破 |
| `fee_records` | 费用台账泄露 |
| `matches` | 订单与双方联系方式泄露 |
| `demands` | 需求单（含 `phone` 字段）泄露 |
| `applications` | 报名关系与快照泄露 |
| `inquiries` / `audit_logs` | 咨询记录 / 操作审计泄露 |

> 验收方式：设完后，用一个**普通用户身份**的小程序客户端尝试直接 `db.collection('parent_users').get()`，应当被拒绝。
> 注意：`demands` 的广场数据是**故意**通过云函数 `getDemands` 下发的（该函数已 `delete safe.phone` 与 `delete safe._openid`），不需要也不应该靠"集合可读"来实现。

## P0 — 云存储权限

路径：**云开发控制台 → 存储 → 权限设置**

`verifications/` 下是老师的学籍认证图片，属敏感个人信息。存储权限不应对所有用户开放读。

> 现有代码中管理端读取图片走的是云函数换取临时链接（`adminReviewVerify` / `adminGetTeacherDetail`），因此收紧存储权限不会影响审核功能。

## P1 — 三个无鉴权云函数（必做）

以下三个函数**原本无需任何身份即可被任意调用**，现已加入 `SETUP_KEY` 闸门。
**最彻底的做法是上线后直接在控制台删除或停用它们**；若暂时保留，必须先配置 `SETUP_KEY`。

| 函数 | 原风险 |
|---|---|
| `adminInit` | `admins` 集合为空时创建 root 管理员，**账号口令由调用方指定** → 集合一旦被清空，任何人可夺取后台 |
| `initDatabase` | 向 `demands`/`teachers`/`resumes`/`fee_records` 灌演示数据（仅当集合为空）→ 任何人可把假老师、假需求灌回生产 |
| `migrateSeedData` | 批量改写 `demands.createTime` |

**处置（二选一）**

1. **推荐**：控制台 → 云函数 → 对应函数 → 删除（或停用）。
2. 保留但加锁：给这三个函数配置环境变量 `SETUP_KEY=<你自己的随机串>`，调用时传 `{ setupKey: '<同一串>' }`。
   未配置 `SETUP_KEY` 时函数**一律拒绝执行**（失败关闭），这是有意设计。

## P1 — 云函数环境变量（必做，漏配会锁死管理端）

路径：**云开发控制台 → 云函数 → 对应函数 → 配置 → 环境变量**

| 变量 | 适用函数 | 值 | 漏配后果 |
|---|---|---|---|
| `ADMIN_PASSWORD_SALT` | `adminInit`、`adminLogin`、`adminChangePassword` | **原代码中的盐值**（`hunnu-tutor-admin-salt-v1`） | 三处哈希不一致，**所有管理员无法登录** |
| `SETUP_KEY` | `adminInit`、`initDatabase`、`migrateSeedData` | 你自定的随机串 | 这三个函数拒绝执行（安全默认） |

> ⚠️ `ADMIN_PASSWORD_SALT` 必须与数据库中已有 `passwordHash` 所用的盐值一致。
> 数据库中现存口令是用历史盐值算出来的，**换值等于所有管理员账号全部失效**。
> 若要轮换盐值，必须先用旧盐值校验旧口令、再用新盐值重算 `passwordHash`（写一次性迁移函数），不能只改环境变量。

改完记得**重新上传部署**这三个（或五个）云函数。

## P2 — 管理员账号

1. **立即确认线上口令不是 `admin123`**。代码中的默认口令已移除，但**线上已存在的账号密码不会自动变化**。
   路径：管理端小程序 → 设置 → 修改登录密码。
2. 确认登录失败锁定生效：连续输错 5 次应返回「账号已临时锁定」，第 6 次即使密码正确也应被拒。
   > 若被恶意打满导致自己被锁，可在控制台 `admins` 集合中清空该账号的 `lockedUntil` 字段立即解锁。
3. 管理端为**多人共用账号**，后登录会顶掉前一个会话。如需严格隔离，按人分配管理员子账号。

## P2 — 已知残留风险（来自《账号与数据隔离说明》第七节）

这些不是漏洞，但属于可被滥用的面，数据量上来后建议处理：

| # | 风险 | 说明 |
|---|---|---|
| 1 | `applyDemand` 报名上限为 check-then-act | 并发下理论可突破 5 条上限或产生重复报名 |
| 2 | 高频查询缺索引 | `demands(status,auditStatus,createTime)` 等；缺索引在大数据量下可被用来拖慢接口 |
| 3 | 老师端报名列表无分页 | 服务端默认 100 条，历史被截断 |
| 4 | `adminDashboard` 费用汇总全表取出 | 台账增大后单次调用耗时/内存上升 |
| 5 | `login` 失败时前端本地降级登录 | 会生成临时 openid 的本地会话；服务端鉴权只看 `getWXContext()`，故不影响越权，但建议改为直接报错阻断 |

## 已完成的代码加固（本次）

| 项 | 说明 |
|---|---|
| `adminLogin` 消除账号枚举 | 「账号不存在 / 已停用 / 密码错误」统一返回同一文案，不再帮攻击者确认有效账号 |
| `adminLogin` 失败锁定 | 连续失败 5 次锁定 15 分钟，锁定期间即使密码正确也拒绝；逻辑抽为 `adminLogin/loginGuard.js` 纯函数，已用 11 项离线测试覆盖 |
| `adminInit` 移除内置默认口令 | 不再创建 `admin/admin123`，首次初始化必须由调用方传入 `initialPassword`（≥ 8 位） |
| 三个无鉴权函数加闸门 | `adminInit` / `initDatabase` / `migrateSeedData` 需 `SETUP_KEY`，未配置则拒绝执行；已用 18 项离线测试覆盖 |
| 凭据移出仓库 | 云环境 ID / AppID 走 `.env`，盐值走云函数环境变量，公开仓库中不再含真实值 |

## 仍需人工核查的项

- [ ] 各集合权限是否为「仅管理端可读写」（P0，**只能你在控制台做**）
- [ ] 云存储权限是否已收紧（P0）
- [ ] 三个无鉴权函数是否已删除或已配置 `SETUP_KEY`（P1）
- [ ] `ADMIN_PASSWORD_SALT` 是否已在三个函数上配置且值正确（P1）
- [ ] 线上管理员口令是否已改掉弱口令（P2）
- [ ] 云函数是否已重新上传部署（改了代码不部署等于没改）
